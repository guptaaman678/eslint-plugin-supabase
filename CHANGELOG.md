## 0.1.0

### Minor Changes

- f7c7ea7: Resolve the role each Supabase client runs as: `settings.supabase.clients` entries by module glob or factory name, then service-role and secret key names or `sb_secret_` literals, then anon and publishable names or `sb_publishable_` literals, then `defaultRoles` (or a skip with `unknownKey: "skip"`). Clients with no traceable origin are skipped. Skips are counted, and `ESLINT_PLUGIN_SUPABASE_STATS=<path>` writes them to `<path>.<threadId>.json` at exit. A `clients[].module` glob with an unclosed `{` is now a settings error.
- 2e40b6b: Fewer false positives found on real projects. A client made by your own factory function (such as `createAdminClient()`, a local helper or a lazily created singleton) now takes its role from the key of the clients the factory returns, up to three factories deep. Key names matching `/service[_-]?key/i` count as service role, and a helper called with a string (`getEnv('SUPABASE_SERVICE_ROLE_KEY')`) is classified by that string. A client wrapped in `new Proxy(...)` or another non-Supabase class is skipped instead of being checked with the default roles. `no-unsent-query` no longer reports a statement that refines a builder variable in place, such as `if (done) query.eq('done', true);`.
- 08ed7a0: Read the database your migrations build through `supabase-grants-lint`'s engine (new dependency `supabase-grants-lint` `^0.3.0`), so the schema rules and grants-lint never disagree. Add `supabase.withProject({ projectDir })` for monorepos and custom project directories. `recommended` recomputes its `migrationsHash` at each config evaluation. The plugin loads its SQL parser with a top-level await, so `require()` of the plugin now fails with a message that shows the CommonJS form that works: `module.exports = import('eslint-plugin-supabase').then(({ default: supabase }) => [supabase.configs.recommended]);`.
- d0e9b3f: Add the plugin frame: a `recommended` flat config for TypeScript files (ignoring `supabase/functions`), validated `settings.supabase` with "did you mean" errors, and peer ranges for ESLint 9.15+ and 10, TypeScript 5.8 to 6.0 and `@typescript-eslint/parser` 8.58+ on Node `^22.13.0 || >=24`.
- b3f3805: Add `supabase/no-unsent-query` (error in `recommended`): reports a lazy Supabase query builder or storage download that is discarded with `void` or left as a bare statement, so the request is never sent. Two suggestions: `await` (inside async functions) and `.then()`.
- d1fa9ee: New rule `realtime-table-published` (error in `recommended`): reports a Realtime `postgres_changes` subscription to a table that your migrations never add to the `supabase_realtime` publication, so it connects and never receives an event. Options `publication`, `ignoreTables`, `reportUnknownTables` and `reportUnresolved`. Membership changed inside a `do` block is skipped, not reported.
- 8d1b9e3: New rule `rls-readable` (error in `recommended`): reports a read, a filtered update or delete, or a Realtime `postgres_changes` subscription by an `anon` or `authenticated` client on a table that has row level security on and no policy admitting the call in your migrations, so it returns or changes nothing with no error. A filtered update or delete also needs a select policy. Service role clients, inserts, upserts and views are not reported. Options `ignoreTables` and `reportUnresolved`.
- 36376f1: Add `supabase/subscribe-status-handler` (warn in `recommended`): reports a Realtime `channel.subscribe()` call with no status callback, or with a callback that declares no parameters, so `CHANNEL_ERROR`, `TIMED_OUT` and `CLOSED` go unnoticed. Option `allowWrappers` names project helpers that already check the status.
- 7d1426a: New rule `table-granted` (error in `recommended`): reports a table call or a Realtime `postgres_changes` subscription when no role the client can run as (including `service_role`) holds every table privilege it needs in your migrations, so the call fails with 42501 or the subscription receives no data. Writes that return rows or filter, and every upsert, also need select; a merge upsert needs update, `ignoreDuplicates: true` does not. Grants to `public` and column grants count. The message names the missing privileges and the grant that fixes them. Options `ignoreTables` and `reportUnresolved`.

### Patch Changes

- b2c0486: When the TypeScript checker throws while typing one expression (TypeScript 6.0.3 can, inside its module-specifier code), the rules skip that expression instead of stopping the lint of the whole file.
- 4976f16: `rls-readable` no longer treats the tables of a `supabase db pull` baseline as having RLS on from the `ensure_rls` trigger. The trigger's function in a baseline now counts from the next migration file, so tables in the baseline keep the RLS state their own statements give, and tables created by later migrations still get RLS from the trigger. Requires `supabase-grants-lint` `^0.3.2`.
- 89b8e19: The documented configs now lint a project with edge functions and `.js` files without errors: the typed-linting block ignores `**/supabase/functions/**`, and every rule override uses the `files` and `ignores` of `recommended`, since an override for every file stops ESLint with `Could not find plugin "supabase"` on a `.js` file. The docs also say that the schema rules check nothing when your migrations do not create your tables, and to run `supabase db pull` for a baseline.
- f955525: A client's key read through a string method without arguments, such as `process.env.SUPABASE_SERVICE_ROLE_KEY!.trim()`, is now classified by the name it is called on. Before, such a service role client was treated as a client-role client, so `rls-readable` reported its reads and writes.
- 2e39e63: `rls-readable` no longer reports a table whose policies a migration creates, alters or drops inside a `do` block. The replay cannot read the block, so the table's policies are unknown: the rule skips the call (reason `policy-uncertain`), and with `reportUnresolved` it names the migration file and line of the block.
- 42423eb: `rls-readable` now considers, for a read, update or delete, only the roles that hold every table privilege the call needs. When no role holds them, the call fails with error 42501 rather than returning nothing, so `table-granted` reports it and `rls-readable` no longer reports it a second time as a silent no-op.
- 89b8e19: The `reportUnresolved` message for a skipped `unknown-client` call now suggests `settings.supabase.clients` only when the client comes from your own factory, which an entry can map. For a client that is itself a function parameter, a `let` or a property, no entry can reach it, and the message says how to have the call checked instead.
- 42423eb: A client from your own factory is now skipped (reason `unknown-client`) when the factory can also return a value the plugin cannot trace, such as a test seam (`client = c` in a setter, or `if (testMake) return testMake();`), and so is a client returned by calling a function parameter, a `let` or a property (`getClient()`). Before, such calls took the default roles, so `rls-readable` reported reads and writes of service role clients. Map such a factory in `settings.supabase.clients` to have its calls checked.
